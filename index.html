Executive recommendation

Build one controlled MCP pilot, not four isolated experiments.

Create a first functional version connecting Claude to Swiss case law and three fitness platforms through one governed architecture. Reuse the community servers for rapid validation, while keeping every provider adapter replaceable.

MCP fundamentals

MCP (Model Context Protocol) is an open standard that lets an AI assistant like Claude connect to external data and services. Think of it as a universal plug between Claude and a platform.

Anatomy of a tool

A tool is a named action the server offers to Claude. Claude reads the description to decide when to use it. Hover a part to see what it does.

"name": "get_sleep_data",
"description": "Average and nightly sleep
  for the last N days",
"arguments": { "days": 7 },
"access": "read-only"

Hover a line

Each part of the definition has a job. The name identifies the tool, the description tells Claude when to use it, the arguments are what Claude fills in, and the access mode decides whether it can change data.

Implementation stage

Why this shape

One door

Users and administrators deal with one stable entry point. Rules, logging and confirmations live in one place instead of being rebuilt per platform.

Swappable parts

Change the Garmin adapter from a community server to the official API without touching Claude or what users see. Use the stage switch above to see the change.

Law and fitness separated

OpenCaseLaw needs no personal credentials. The fitness adapters only run with the user’s own tokens and only for the pilot group.

Open point: the existing Microsoft sign-in in bear_backend may be reusable for the gateway. This needs confirming before the design is final.

Platform dossiers

Four very different platforms. Each dossier covers what it holds, the tools exposed, how sign-in works and what to watch. Scores are our own assessment from testing and reading the repos.

Security & access

Law is for everyone in the firm. Fitness is for a selected group. Each person connects their own account and nobody else can see it.

View permissions as

Phase 1 is read-only. “Confirm first” applies once write actions are switched on in phase 2.

How a personal account gets connected

Step through the sign-in and token journey. Passwords and cookies are never shared between users.

What is stored

Kept by the gateway

  • Per-user provider tokens, encrypted
  • Group membership (from the firm’s directory)
  • Audit entries: user, tool, time, allowed or refused

Not kept by the gateway

  • Search text or fitness values returned to Claude
  • Shared passwords or shared cookies
  • Anything for users outside the allowed group

What Claude itself retains depends on the firm’s Claude plan settings, to be confirmed with the plan owner.
